# ML Task — Particle Trajectories Classification

Учебный проект по анализу данных и решению задачи многоклассовой классификации с использованием методов машинного обучения.

Цель проекта — построение модели, способной определять тип траектории частицы (`converging`, `diverging` или `oscillating`) на основе пяти числовых параметров.

## Содержание проекта

| Файл | Назначение |
|---|---|
| `ml.ipynb` | Jupyter Notebook с исследовательским анализом данных, обучением моделей, подбором гиперпараметров и оценкой результатов |
| `particle_trajectories.csv` | Исходный набор данных |
| `requirements.txt` | Список используемых Python-библиотек |

## Данные

Датасет содержит 20 000 наблюдений и 6 столбцов: пять числовых признаков и одну целевую переменную.

**Используемые признаки:**

- `x0`
- `v0`
- `V0`
- `x0_scale`
- `gamma`

**Целевая переменная:** `trajectory_type`.

Выделяются три класса траекторий:

- `converging` — сходящиеся траектории;
- `diverging` — расходящиеся траектории;
- `oscillating` — осциллирующие траектории.

Распределение целевой переменной:

| Класс | Количество | Доля |
|---|---:|---:|
| `converging` | 7 423 | 37,12 % |
| `diverging` | 7 142 | 35,71 % |
| `oscillating` | 5 435 | 27,18 % |

В имеющейся версии CSV отсутствуют пустые поля и полностью дублирующиеся записи.

## Выполненные этапы

### 1. Исследовательский анализ данных (EDA)

- Загрузка и первичное изучение набора данных.
- Анализ распределения целевых классов.
- Визуализация фазового пространства по признакам `x0` и `v0`.
- Построение boxplot-графиков для анализа распределения числовых признаков.

### 2. Подготовка данных

- Кодирование целевой переменной с помощью `LabelEncoder`.
- Разделение данных на обучающую и тестовую выборки в соотношении 70/30.
- Использование стратифицированного разделения для сохранения пропорций классов.
- Фиксация `random_state=42` для воспроизводимости случайных операций.

В результате получены:
- Обучающая выборка — 14 000 наблюдений.
- Тестовая выборка — 6 000 наблюдений.

Для моделей Logistic Regression и MLP стандартизация признаков выполняется с помощью `StandardScaler`, включённого в `Pipeline`. Это позволяет корректно проводить кросс-валидацию без утечки информации из проверочных фолдов.

Для Random Forest стандартизация не применяется.

### 3. Обучение моделей

В работе рассматриваются три алгоритма классификации:

**Logistic Regression**
- Линейная модель классификации.
- Используется в качестве базового метода сравнения.

**Random Forest Classifier**
- Ансамбль деревьев решений.
- Позволяет учитывать нелинейные зависимости между признаками.

**Multi-layer Perceptron (MLP)**
- Многослойный перцептрон.
- Используется для моделирования нелинейных зависимостей между входными признаками и целевыми классами.

### 4. Подбор гиперпараметров

Для поиска подходящих конфигураций моделей используется `RandomizedSearchCV`.

Применяется 5-кратная стратифицированная кросс-валидация (`StratifiedKFold`), позволяющая сохранять пропорции классов в обучающих и проверочных фолдах.

Количество проверяемых комбинаций:
- Logistic Regression — 30;
- Random Forest — 50;
- MLP — 30.

В качестве основной метрики при подборе гиперпараметров используется Accuracy.

Для Logistic Regression и MLP предварительная стандартизация включена непосредственно в `Pipeline`. Благодаря этому на каждом фолде параметры масштабирования вычисляются только по соответствующей обучающей части данных.

### 5. Оценка качества моделей

После подбора гиперпараметров модели оцениваются на отдельной тестовой выборке.

Используемые метрики:

- **Accuracy** — доля правильно классифицированных объектов.
- **Balanced Accuracy** — средняя полнота классификации по отдельным классам.
- **F1-macro** — среднее значение F1-score по классам без учёта их размера.

Дополнительно строятся матрицы ошибок (`Confusion Matrix`) для анализа результатов классификации каждого класса.

Для MLP также визуализируются границы решений в пространстве двух признаков (`x0`, `v0`). При построении двумерной проекции остальные признаки фиксируются на медианных значениях тестовой выборки.

## Результаты

Итоговые метрики моделей на тестовой выборке:

| Модель | Accuracy | Balanced Accuracy | F1-macro |
|---|---:|---:|---:|
| Logistic Regression | 0,5138 | 0,4729 | 0,4158 |
| Random Forest | 0,9322 | 0,9285 | 0,9277 |
| **MLP** | **0,9608** | **0,9588** | **0,9582** |

Лучший результат показала модель MLP.

Лучшая конфигурация MLP, найденная в ходе подбора гиперпараметров:

| Параметр | Значение |
|---|---|
| `hidden_layer_sizes` | `(100,)` |
| `activation` | `tanh` |
| `solver` | `adam` |
| `alpha` | `0.00375` |
| `learning_rate_init` | `0.00124` |
| `max_iter` | `500` |

Лучшая Accuracy MLP на этапе кросс-валидации составила **0,9626**, итоговая Accuracy на тестовой выборке — **0,9608**.

Таким образом, в рамках проведённого эксперимента MLP показала наилучшее качество классификации среди рассмотренных моделей.

## Запуск проекта

```bash
cd ML_task
```

2. Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

```bash

```

Представленные метрики относятся к конкретному разбиению данных и конфигурациям моделей, использованным в эксперименте. Они не гарантируют аналогичное качество классификации на других наборах данных.
